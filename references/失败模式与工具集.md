## 失败模式与处理

所有异常必须记录到 `_failed_<date>.json`，不静默跳过。

| 触发条件 | 一线处理 | 仍失败兜底 |
|---|---|---|
| `view_file` 无法加载视频 | 检查文件格式（mp4/mov），确认文件未损坏 | 记录到 `_failed_<date>.json`，告知用户具体文件名和错误 |
| **流传输中断 · 上传阶段**（`write: broken pipe` / EPIPE / `stream_receive_count:0`） | Sidecar 拒收超大请求体（base64 膨胀 ~1.33×）。检查文件是否 >10MB：重跑 `preprocessor.py` 生成 `_sense.mp4`，新会话用 `view_file_target` 继续——**不要点 Continue**，断裂的流式上下文无法恢复，必须从 `PREPROCESSED` 状态重进 Layer 2 | 感知轨仍失败 → 启用**紧急降级模式**（见下文）：`_sense_audio.m4a` + `_contact_sheet.jpg` 组合感知 |
| **流传输中断 · 等待响应阶段**（`read: connection reset by peer`） | 同上：感知轨 + 新会话从 `PREPROCESSED` 重进；并做**网络层自查**（代理 NO_PROXY 含 127.0.0.1/localhost；Sidecar 超时 ≥300s） | 同上传阶段兜底 |
| 视频超过 5 分钟 | 运行 `scan_helper.py --smart-split` 按 ffmpeg 静音/转场自动切片，分段 `view_file` 观看（大文件先转码再切片，可叠加） | 仍失败则记录并告知用户 |
| Gemini 感知返回非 JSON（含 markdown 包裹） | 手动提取 JSON 块，重新感知一次 | 简化为单板块逐次感知，逐板块保存 |
| 某板块 JSON 字段为空/缺失 | 对该板块单独补感知 | 报告中标注「未提取到此字段」，不编造值 |
| 批量感知部分视频失败 | 读 `_failed_<date>.json`，逐个重跑 | 最终失败的标注并告知用户 |
| 归档目录无写权限 | `chmod -R +w <archive-dir>` | 切换到用户目录 `~/对标视频分析资产/` |
| 扫描中途中断 | 重跑 `scan_helper.py --incremental`（自动跳过已归档） | 查 `_scan_log.json` 确认已完成列表，手动指定未完成视频补跑 |
| **会话死亡（L2→L3 间隙）** | `session_guard.py preflight` 找到卡在 `FLASH_EXTRACTED` 但无 `_pro_review_packet.json` 的视频 → 立即跑 L3 阶段A（秒级脚本，零流式）→ 状态机续跑 | 新会话从 `PRO_AUDITING` 继续，零损失 |
| **单轮输出上限中断**（L2 感知完成但 analysis 未落盘，状态仍 PREPROCESSED，事故 2d8ee957） | 若同一会话上下文仍在：续接后**第一动作就是分批把板块 JSON 写盘**（禁止再看视频/查资料/重新推理），写齐 5 板块后立即 `finalize-l2`；Pro 阶段B 抽查会验证证据真实性，凭记忆写盘的风险由门禁兜底 | 上下文已丢失 → 从 `PREPROCESSED` 重进 L2，严格执行渐进落盘铁律（每板块感知完立即写盘） |
| **会话预算耗尽**（连续处理 ≥3 条视频后上下文膨胀） | `session_guard.py preflight` 检查预算 → 开新会话，状态机续跑 | 损失仅限"未完成的当前条"——L2 落盘后立即跑 L3 可使损失为零 |
| **状态机被手写篡改**（`attempts` 字段/早产标记/history 缺失） | `session_guard.py validate-state` 检测篡改 → 根据 `analysis_*.json` 实际产出重新校准状态 | 状态不可信时用 `session_guard.py mark-flash-extracted` 重标（幂等） |
| **会话上下文被平台截断/压缩**（L2 中途断点记忆丢失，2026-07-26 AccountA02） | **不信记忆，以磁盘为准**：读 `_state.json` + 已落盘 `analysis_<date>.json` 盘点已完成板块（渐进落盘铁律保证磁盘反映真实进度），只补缺失板块，末板块写完同回合 finalize-l2 | `session_guard.py preflight` 全账号扫描定位断点；已落盘板块的真实性由 Pro 阶段B 抽查兜底 |
| **宿主工具层不支持视频 view_file**（报 `unsupported mime type video/mp4`，2026-07-26 AccountA02 Pro 阶段B） | L2 原生感知**禁止在该宿主继续**（换到支持 Gemini 原生视频的环境执行，不得用九宫格/音轨推断冒充）；Pro 阶段B 可派发支持原生视频的 Pro 模型 subagent 持审查包执行抽查（审查包自足，回收结果照常 `--ingest-pro-result`；按规则 5 登记派发并二次验证产出） | 仍无可用环境 → 记录 `_failed_<date>.json` 并告知用户，禁止降级为非观看式抽查 |

### 紧急降级模式（音视解耦 · 最后兜底）

> **定位**：`_sense.mp4` 感知轨仍传输失败时的**应急路径**，避免单个 HTTP 失败导致整条视频分析死锁。不是常规工作流，禁止主动选用（反例 #9 依然有效）。

**触发条件（必须同时满足）**：
1. 已生成 `_sense.mp4` 感知轨且 `view_file` 加载仍失败（broken pipe / connection reset）
2. 网络层自查已完成（NO_PROXY / Sidecar 超时）仍无效

**执行方式**：
1. `view_file` 加载 `_sense_audio.m4a`（2~3MB 独立音轨，Gemini 原生支持音频感知）→ 完成 audio / narrative(VO) 板块感知
2. 查看 `_contact_sheet.jpg` 九宫格 → 完成 cinematography 的场景/机位/色彩粗粒度感知（仅场景级，无毫秒级镜头时间轴）
3. `ai_fx` / `sop` 板块基于可见信息填写，无法确认的字段一律 `null`

**强制诚实标注**：
- `_meta.analysis_method` 记为 `audio_contact_sheet_degraded`
- `honesty_report.watched_full_video = false`，`fields_not_from_viewing` 列出所有非真实观看字段
- `shot_timeline` / `sfx_timeline` 密度要求**自动豁免**（九宫格无法提供毫秒级时间轴），但必须在 honesty_report 说明豁免原因
- Pro 质检时按降级标准审查：重点查"音频感知内容是否真实"，不因缺少逐镜时间轴直接判 0 分
- 该视频的 analysis 在 `account_formula` 提炼时**只参与音频/叙事维度统计**，镜头维度不计入 ASL 均值（避免污染账号基线）

**状态机**：降级产出仍走 Layer 3 质检，通过后状态正常推进，但 `_state.json` 会记录 `degraded: true` 供时序追踪甄别。

## 自定义分析

内置 5 板块不够时，直接在 `view_file` 观看视频后应用自定义量化观察提示词：

1. 运行 `scan_helper.py` 获取视频列表和归档路径
2. 对目标视频执行 `view_file` 直接观看
3. 应用你的自定义提示词（遵循"只做量化观察，不要求推理"原则）
4. 将结果保存到对应归档路径

自定义提示词遵循"只让 Gemini 量化观察，不要求推理"原则（见 [references/analysis_framework.md](references/analysis_framework.md) 末尾）。

## 正式工具集

| 脚本 | 用途 | 使用时机 |
|---|---|---|
| `schema_contract.json` | **字段级唯一事实源**（各校验脚本的必填表均从它读取；带 version 字段） | 改 prompts.json 字段后必同步 |
| `scan_helper.py` | 扫描视频文件、创建归档结构；`--init-account` 轻量建账（_account_meta/_scan_log/_index）；`--cleanup-sense` 清理已交付视频的过程文件（默认 dry-run，`--apply` 执行，`--quarantine-dir` 移至隔离区而非删除） | 第 0/1 步 / 批次交付后清理 |
| `session_guard.py` | 会话寿命管理：**`finalize-l2` L2 收尾一键化（推荐入口：验证+密度门禁+标记+L3 阶段A 组包同进程连跑，原子绑定间隙物理消失）**；`emit-l2-skeleton` 从契约生成 analysis 骨架+必填清单（写前预检机械化，杀死凭记忆构造）；`mark-flash-extracted` 单步验证+标记（保留兼容），含密度门禁（镜头/ASL/SFX/VO 按 `density_gates` 分档校验）；`preflight` 开工前扫描卡住视频+watchdog 遗孤识别+预算追踪+优先行动清单；`validate-state` 检测状态篡改 | L2 开工前（骨架/前检查）/ L2 落盘后（finalize）/ 异常排查（篡改检测） |
| `preprocessor.py` | Whisper STT + ffprobe + 九宫格切帧（精确 9 帧）+ 账号 Baseline 注入 + **感知专用转码（>10MB 自动 `_sense.mp4` + `_sense_audio.m4a` 降级音轨）** | Layer 1 预处理 |
| `batch_preprocess.py` | 批量 L1 驱动（每账号一次调用，幂等跳过已处理/在途视频，`--dry-run`/`--limit` 支持）；纯本地 CPU 工作，适合会话外一次性跑完全库 | 批量 L1 预跑（提速） |
| `merge_subagents.py` | 实验模式主节点缝合器：收 3 个 Subagent 分块 → 物理硬截断 + 卡点对齐补 triad_coupling + 密度预检（不达标输出定向补感知指令）+ 组装标准 analysis | 单视频模态并发（实验） |
| `validate_schema.py` | 单文件 schema 验证 + 偷懒检测；**honesty 观看时长 vs `_video_meta.json` 真实时长硬比对（±1s）**；SFX 三元耦合覆盖率 ≥50% 检查；`--check-contract-sync` 校验 prompts↔契约对齐 | Layer 3 硬门禁 / 改提示词后 |
| `ab_compare.py` | A/B 对比回归工具（skill 流水线 vs 直接 prompt，三路胜负判定，等值判 tie）；`--json-out` 供回归脚本消费 | skill 改版后回归 / 对照实验 |
| `pro_qa_inspector.py` | 两阶段质检：规则硬门禁+预检 → 组装 Pro 审查包（含 analysis_md5）→ 回收 Pro 3.1 语义终审结果，驱动状态机与熔断，轮次自动归档 | Layer 3 语义质检 |
| `ip_sop_compiler.py` | IP 专属实拍与音频 SOP 自动编译（切频内联计算）+ 回写 _index.json | Layer 4 资产编译 |
| `asset_pool_archiver.py` | 音效库持续归档（--rebuild 幂等重灌） | Layer 4 资产池 |
| `sfx_audit.py` | 音效库体检（对账/时间戳越界/漏归档；结构性问题 exit 1） | Layer 4 资产池守护 |
| `build_video_catalog.py` | 视频目录聚合（类型/叙事节拍/时长） | 音效决策台数据层 |
| `sfx_enrich.py` | 音效四维打标 v2（规则主 + v2_patch.json 补丁） | 音效决策台数据层 |
