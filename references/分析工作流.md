## 分析工作流

### Layer 1：信号显性化预处理（脚本自动执行）

> **为什么需要预处理？** LLM 盲看视频时会遗漏极速台词、卡点转场与微弱音效。预处理将这些信号"显性化"，为 Flash 感知提供 Ground Truth。

**执行命令**：
```bash
python3 scripts/preprocessor.py \
  --video /path/to/video.mp4 \
  --archive-dir /path/to/archive \
  --account "kat-and-oliver" \
  --video-id "TOP01_xxxx" \
  # 可选：--sense-threshold-mb 10（默认 10）/ --no-sense（强制原文件直传）
```

**批量模式（2026-07-26 提速优化）**：L1 是纯本地 CPU 工作（零 LLM 感知，不受「禁止并行派发」约束），应在会话外一次性批量跑完全库，之后每个会话开局即进 L2：

```bash
python3 scripts/batch_preprocess.py \
  --videos-dir /path/to/account_videos \
  --account "kat-and-oliver" \
  --archive-dir /path/to/archive
```

幂等可重复执行：已有 `_state.json` 且状态 ≠ `UNPROCESSED` 的视频自动跳过（保护在途/已交付分析）。

**产出**：`_grounding_payload.json`
- `_system_boundary`: **物理锚点硬基线（2026-07-26 新增）**——`strict_duration_sec`/`strict_fps`/`total_frames`/`time_range_rule`，随 prompt_header 强制注入每个板块（含 Subagent）头部，封死超时长幻觉；门禁层对越界时间戳硬拒（+0.5s 容差）
- `_scene_cut_estimate`: **算法切点锚点（2026-07-27 新增，A/B 02 号欠切事故）**——ffmpeg scene>0.35 硬切点计数，作为 shot_timeline 量级参照；prompt 层约束「镜头数应与该量级一致，快切视频禁止按档位合并」；门禁层软告警（<50% 涉嫌漏切，>2.5× 涉嫌填充），不拒收（scene 检测会过检）。**2026-08-04 监督审计补充**：软告警仅在 est≥10 时启用（低切视频硬切点少，锚点解释力弱）；上限风格感知——honesty 声明低切/手持/POV/长镜头/简笔动画等软切风格时上限放宽至 4.0；honesty_report 须注明风格与镜数划分依据，供跨次对比解释镜数波动
- `whisper_stt`: 逐句 `[start_sec, end_sec, text]` 列表 — 作为 VO 转录的 Ground Truth
- `ffprobe_meta`: 时长/分辨率/帧率/编码 — 已有 `_video_meta.json`
- `contact_sheet_path`: 九宫格拼接切片图路径（始终生成：按总帧数等距精确抽 9 帧填满 3×3，辅助 Pro 抽查视觉对齐；时长 <1s 自动跳过）
- `account_baseline`: 账号历史统计（ASL 均值、低机位占比等）
- `sense`: 大文件感知轨信息（原文件 >10MB 时生成；含原/转码体积、转码档位、时长校验结果、`audio_path` 独立音轨），无需转码时为 `null`
- `view_file_target`: **Layer 2 实际应加载的文件路径**（有感知轨 → `_sense.mp4`；无 → 原文件）

**感知专用转码规则**：
- 触发：原文件体积 > `--sense-threshold-mb`（默认 10MB，2026-07-26 由 20MB 下调：断管代价是整段 L2 重来，更小请求体压低失败率与传输耗时）
- 档位：① 720p / H.264 CRF30 / superfast / AAC 96k → 仍超阈值则 ② 540p / CRF34 / AAC 64k / fps≤30
- 完整性：产物时长与原片偏差 >1s 视为转码异常，自动重试下一档；全档失败回退原文件并告警
- 音视解耦：转码成功同步提取 `_sense_audio.m4a` 独立音轨（2~3MB，传输成功率 ~100%），作为紧急降级资产
- 一致性：有感知轨时九宫格从感知轨切帧，保证 Pro 抽查所见画面与 view_file 严格一致
- Whisper STT 始终对**原文件**执行（保音频保真度）

**状态更新**：`UNPROCESSED` → `PREPROCESSED`

### 第 0 步：账号类型预判（Agent）

观看前 15-30 秒（覆盖 3-5 个镜头切换）判断类型，决定重点板块：

| 账号类型 | 重点板块 | 可弱化 |
|---|---|---|
| 纯实拍 | cinematography, audio, narrative | ai_fx |
| AI/CG 合成 | cinematography, ai_fx, sop | — |
| 快切拟人 | cinematography, audio, narrative | ai_fx（除非用 AI 微动） |
| 简笔画/动画 | ai_fx, narrative, sop | cinematography |
| 口型微动 | ai_fx, audio | sop |
| 混合/不确定 | 全部 5 板块 | — |

### Layer 2：Flash 3.6 多模态感知（单视频逐条）（强制 batch_size=1）

> **强制单视频模式**：每次只处理 1 条视频。用 `view_file` 真实观看完整视频后输出 5 板块 JSON + 诚实度报告，审查者验收通过后才可处理下一条。禁止批量处理，禁止编写 `apply_*.py` 等脚本。

> 🔴 **CRITICAL · 必读**：你必须使用 Gemini 3.6 Flash 的**原生多模态能力**，通过 `view_file` 直接观看完整视频（画面 + 音频轨同时感知）。
>
> **禁止使用** video-tagger、qwen3-vl-plus、DashScope、Python API 脚本或任何外部工具/API 替代原生感知。
>
> **禁止降级为抽帧/切片分析**——如果 `view_file` 无法加载某条视频，立即在 `_failed_<date>.json` 中记录并告知用户，不要自行降级到帧提取。

   创建 `_account_meta.json` + `_scan_log.json` + 全局 `_index.json`。跳过此步会导致 Layer 1 baseline 注入恒为 unknown/0，增量扫描与时序对比无法工作。

1. 运行辅助脚本，列举视频文件并创建归档结构：

   脚本输出 JSON 包含：视频列表、每条视频的归档路径、输出文件路径、ffprobe 硬指标元数据。

2. 🔴 **写前预检铁律（Pre-flight Read · 2026-07-26 新增，事故：铁头阿彪02 finalize-l2 连续 3 轮门禁失败）**：开始任何感知或写 JSON 之前，必须按顺序**真实读取**以下三个文件，**禁止凭记忆或凭 SKILL.md 的文字描述构造 JSON 结构**：

   | 顺序 | 文件 | 目的 |
   |---|---|---|
   | ① | `scripts/schema_contract.json` | 必填字段唯一事实源——按 `sections.<板块>.top / macro` 清单逐一对照填写（历史事故：跳过此步一次漏 9 个契约必填字段，如 `ai_fx.facial_animation`、`narrative.script_full_text`、`sop.complexity_breakdown` 等） |
   | ② | `scripts/prompts.json` + `scripts/prompt_header.json` | 各板块输出结构 + Ground Truth 注入模板 |
   | ③ | `_grounding_payload.json` | 获取 `view_file_target` + Whisper STT + `_system_boundary` 物理边界 |

   读完后按 `prompt_header.json` 将 payload 中的 Whisper STT / ffprobe 硬指标 / 账号 Baseline **注入每个板块 prompt 头部**（Ground Truth 锚定，防编造的关键步骤，禁止省略）。

   **预检机械化（推荐，2026-07-26 新增）**：运行骨架生成器代替人工对照契约——
   ```bash
   python3 scripts/session_guard.py emit-l2-skeleton \
     --account "kat-and-oliver" --video-id "TOP01_xxxx" --date 2026-07-26
   ```
   输出含全部契约必填字段的骨架 JSON（含 `_meta.honesty_report` 嵌套结构、`analysis_method`）+ 逐板块必填清单，照骨架填空即可一次过结构门禁。骨架 honesty 预置 false、timeline 预置 \[\]，不真实填写必被 finalize-l2 拒绝；**禁止把骨架直接另存为 `analysis_<date>.json`**（会被 watchdog 误认为感知产物，命令层已对此硬拒）。

   > 为什么这条是铁律：finalize-l2 硬门禁只能**事后**拦截，每拦一轮就多付一轮修补代价（3 轮中断 = 3 倍成本）。预检把结构对齐提前到写入前，一次写对。

3. 对每条视频逐条执行**原生多模态感知**：

   a. 使用 `view_file` 加载并直接观看**完整视频**（含音频轨）——加载路径取 `_grounding_payload.json` 的 `view_file_target` 字段（大文件已自动替换为 `_sense.mp4` 感知轨，禁止绕过感知轨直传原文件）

      🔴 **空返回 = 感知失败（2026-07-26 新增）**：若 `view_file` 响应中没有任何实际音视频内容（如仅返回一行 "The following is the entire, complete content..." 而无画面/声音信息），视为**本次感知失败**——禁止在 honesty_report 写 `view_file_called: true` / `watched_full_video: true`，禁止用 Whisper STT + `_contact_sheet.jpg` 的推断结果冒充原生多模态感知（这是诚实度造假）。只有两条合法出路：重试 view_file（可换 `_sense.mp4` 感知轨），或显式走「紧急降级模式」（`analysis_method` 记 `audio_contact_sheet_degraded` 并强制标注全部非观看字段）。
   b. 依次应用 5 板块提示词（从 `prompts.json` 读取），每板块可独立感知一次以确保专注
   c. 对每个板块输出严格符合 `prompts.json` 中 JSON schema 的结构化数据
   d. **只做量化观察**（机位 cm、镜头秒数、f 值、K 值、SFX 秒数、画外音逐句），不做推理判断
   e. 将 5 板块合并为一个 JSON 文件，格式：
      ```json
      {
        "_meta": {
          "video_file": "文件名",
          "video_id": "视频ID",
          "account": "账号名",
          "analysis_date": "YYYY-MM-DD",
          "model": "gemini-3.6-flash",
          "analysis_method": "view_file_multimodal",
          "sections": ["cinematography","ai_fx","audio","narrative","sop"],
          "honesty_report": { "...见「诚实度报告机制」章节完整结构..." }
        },
        "cinematography": {该板块JSON},
        "ai_fx": {该板块JSON},
        "audio": {该板块JSON},
        "narrative": {该板块JSON},
        "sop": {该板块JSON}
      }
      ```

      🔴 **位置铁律（2026-07-26 新增）**：`honesty_report` 必须位于 **`_meta` 内部**，不是顶层键（历史事故：写到顶层导致 finalize-l2 报 honesty_report 缺失）；且其 `sections` 必须覆盖全部 5 板块，每个板块子结构必须含 `view_file_watched: true` + `evidence`（只填顶层 `view_file_called` 不够，门禁逐板块校验 `view_file_watched`）。
   f. 保存到 `<archive-dir>/<account>/videos/<video-id>/analysis_<date>.json`

      🔴 **渐进落盘铁律（2026-07-26 新增，事故 2d8ee957）**：禁止把 5 板块感知结果全部攒在上下文里、最后一次性输出巨型 JSON——214s 视频的 5 板块全量 JSON 曾触发单轮输出上限，感知完成但未落盘，成果随会话蒸发，只能重看。**正确做法：每完成一个板块的感知，立即把当前已完成板块写入/更新 `analysis_<date>.json`**（同一文件迭代更新，末板块写完即为完整文件）。半成品文件无风险：状态机仍是 PREPROCESSED，finalize-l2 会校验 5 板块齐全才放行；会话死亡时已落盘板块不丢，续跑只补缺失板块。

   h. 失败的视频记录到 `_failed_<date>.json`

**感知质量要求**：
- 逐镜时间轴**必须覆盖全片**，不遗漏任何一个镜头切换
- 逐句画外音转录**必须完整**，不跳过任何一句台词/旁白/字幕
- 逐个 SFX **必须不遗漏**，包括微弱环境音
- 微动作微表情**必须捕捉**（宠物歪头/吐舌/眼神/耳朵/肢体），这是 Gemini 独有能力，不可省略
- 跨模态关联**必须标注**（SFX 卡点切镜、BGM 与情绪同步、旁白与画面互补）
- 无法确定的字段返回 `null`，不猜测不编造

**感知密度要求（防偷懒）**：

多轮实跑发现大模型有「不论视频时长都只输出固定数量条目」的偷懒倾向。以下为最低密度要求，低于此密度视为偷懒。

> **口径说明（2026-07-26 统一）**：镜头/SFX 密度下限按视频时长分档，与「自适应粒度适配器」一致——60-300s 中长视频走分镜/场景级（ASL 3-8s 为合理区间），不再套用"每 3 秒 ≥1 镜"的短视频标准。分段阈值的唯一事实源是 `scripts/schema_contract.json` 的 `density_gates`，门禁由 `session_guard.py finalize-l2`（或 mark-flash-extracted）在 L2→L3 绑定点自动执行，不达标拒绝标记 FLASH_EXTRACTED。

| 时间轴 | 短视频 (0-60s) | 中长视频 (60-300s) | 单条上限 | 说明 |
|---|---|---|---|---|
| `shot_timeline` | 每 3 秒 ≥1 镜（≥3.3/10s），ASL 0.5-4s | ≥1.5 镜/10s，ASL 3-8s | 单镜 ≤60 秒 | **例外**：POV/手持长镜头风格视频可降至 2.0/10s（短）或 1.0/10s（中长），但必须在 honesty_report 中说明拍摄风格导致镜头少的原因 |
| `voiceover_transcript` | 每 10 秒 ≥1 句 | 每 10 秒 ≥1 句 | 单条 ≤10 秒 | 30 秒视频 ≥3 句，60 秒 ≥6 句。禁止只分 3 块覆盖全片 |
| `sfx_timeline` | 每 10 秒 ≥2 个 | 每 10 秒 ≥1 个 | — | **必须包含次要环境音**：衣服摩擦声、脚步声、坐垫压陷声等微弱音效不可遗漏。≥50% 的 SFX 须标注 `triad_coupling`（画面+SFX+Ducking 联动） |
| `emotional_timeline` | 每 30 秒 ≥1 段 | 每 30 秒 ≥1 段 | 单段 ≤60 秒 | 30 秒 ≥3 段，60 秒 ≥4 段，180 秒 ≥6 段。禁止固定 4 段 |
| `story_beats` | 每 60 秒 ≥1 个 | 每 60 秒 ≥1 个 | — | 短视频可 2-3 个，长视频 6-10 个 |

**输出前自检（Gemini 在感知阶段必须执行）**：
1. `macro.total_shots` == `len(shot_timeline)`？
2. `macro.avg_shot_length_sec` == `sum(duration_sec) / len(shot_timeline)`（保留 2 位小数，如 2.66；展示层四舍五入到 1 位）？
3. `shot_timeline` 最后一条 `end_sec` ≈ 视频总时长（±1 秒）？
4. `macro.voiceover_ratio_pct` == `sum(end_sec - start_sec) / 总时长 × 100`？
5. `climax_sec` 和 `reversal_sec` 不相同？
6. 所有金句 `text` 是视频中的原文，不是模板/标题/占位符？
7. `narrative_template` 中的时间区间是根据视频实际时长计算的，不是固定的 `0-3s/3-15s`？
8. 对照 `schema_contract.json` 的 `sections.<板块>.top / macro` 清单，5 板块必填字段全部存在？
9. `honesty_report` 位于 `_meta` 内，且 `sections` 下 5 个板块均含 `view_file_watched: true` + `evidence`？

### 实验模式：单视频模态并发（Subagent Concurrent · 2026-07-26 新增）

> 🔒 **评估结论（2026-07-27）：暂缓转正，冻结在实验通道**。两条 A/B 实测（铁头阿彪 03/02）：① 提速未兑现（wall-clock 与单体相当，并发卖点不成立）；② 质量喜忧参半——03 号切分更细（Pro 95/密度↑/真实 triad 100%），02 号快切视频欠切一半（66 镜 vs 算法实测 ~185 切点，判据② FAIL）；③ 跨模态感知未退化（两条真实 triad 均 100%，缝合器零代补）。副产品已反哺主流程：算法切点锚点（L1 `_scene_cut_estimate` + prompt 量级约束 + 门禁软告警）。代码（merge_subagents.py）保留可用，待平台具备真并发提速能力后重新评估。

> 与上方禁令的区别：禁的是「一次并发处理多条视频」；本模式是「同一条视频内按模态拆 3 个专注 Subagent 并发」，每个 Subagent 上下文更短更专注。风险（模态拆分破坏原生跨模态感知、Subagent 编造）由缝合器硬截断 + 密度预检 + Pro 阶段B 全量抽查兜底。

**分工**（每个 Subagent 注入同一份 prompt_header 物理边界 + 对应板块 prompts）：

| Subagent | 负责板块 | view_file 加载 | 产出文件 |
|---|---|---|---|
| visual | cinematography + ai_fx | 完整视频（view_file_target） | `_sub_visual_<date>.json` |

### 第 3 步：账号级公式提炼（Agent）
