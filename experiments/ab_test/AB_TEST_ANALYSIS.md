## 三、🔴 核心发现：Path B 时间轴幻觉 39 秒

### 事实

| | A (skill) | B (direct) | 真实值 |
|---|---|---|---|
| 最后镜头 end_sec | 117.84 | **157.0** | 117.84 |
| VO 最后段 end_sec | 117.84 | **157.0** | 117.84 |
| 时间轴超出 | 0s | **39.16s** | — |
| VO ratio (计算) | 96.6% | **126.1%** | 应≤100% |

### 分析

尽管 `prompt_b.txt` 明确写了 **"请先用 view_file 观看完整视频（含音频轨），不要只抽帧或看切片"**，Path B 仍然产生了超出真实视频时长 33% 的时间轴内容。这强烈表明：

1. **B 可能没有真正执行 view_file**，而是基于对视频的片段印象"脑补"了完整内容
2. **B 的时间戳不可信**——镜头 28（59.2s-103.8s）跨度达 44.6s，这在 25fps 短视频中极不正常，很可能是 B 把多个镜头合并或直接跳过了大段内容
3. **B 的 VO ratio = 126.1%** 在物理上不可能（旁白总时长超过视频总时长），这直接证明了时间戳的系统性错误

### 对比：A 为什么没幻觉

Skill 的 `_meta.honesty_report` 强制要求每个 section 标注 `view_file_watched: true` + 提供从观看中获得的 `specific_details_only_from_watching`（共 21 条），并且 honesty_report 中记录了 `view_duration_sec: 117.84`——与 ffprobe 一致。这形成了一个事实校验闭环。

## 四、Skill 的真实价值：不是"更多"，而是"更准"

### 4.1 Skill 赢的维度（准确性与完整性）

| 维度 | A | B | 意义 |
|---|---|---|---|
| **时间轴准确性** | 100% 覆盖，0 偏差 | 66.8% 覆盖，39s 幻觉 | 🔴 最关键 |
| **VO 密度** | 61 段 / 5.2 per 10s | 35 段 / 3.0 per 10s | skill 把旁白切到句子级 |
| **VO ratio 校验** | ✅ 一致 | ❌ 126.1%（不可能） | skill 有 macro 自检 |
| **诚实度报告** | ✅ 21 条观看证据 | ❌ 无 | skill 强制 accountability |
| **情绪曲线结构化** | 5 段（list+intensity） | 0（dict 格式偏差） | skill Schema 强制 |
| **Ducking 结构化** | 2 事件（list） | 0（文字描述） | skill Schema 强制 |

### 4.2 B 赢的维度（数量，但被幻觉污染）

|---|---|---|---|
| 镜头数 | 21 | 41 | B 的镜头 28-41 大量时间戳>117.84s，属幻觉 |
| SFX 数 | 6 | 11 | B 的 SFX 有 `sec: 123.5, 136.5, 145.2` 超 117.84s |
| BGM 变化 | 3 | 8 | B 的 BGM 段延伸至 157s |
| 微动作 | 3 | 5 | B 的微动作有 `timestamp_sec: 140.5` 超 117.84s |

### 4.3 Skill 自身的密度门禁未达标

| 门禁 | 最低要求 | A 实际 | 状态 |
|---|---|---|---|
| 镜头密度 | ≥3.3/10s | 1.8/10s | ❌ 未达标 |

**Skill 在镜头和 SFX 密度上未达到自身设定的最低标准。** 这解释了为什么 skill 比 B "少"——不是 B 多了，而是 A 自己不够密。但 A 的低密度是真实的（时间轴准确），B 的高密度是幻觉的。

## 五、回答原始问题：为什么 Skill 慢？

| 慢的因素 | 具体表现 | 是否值得 |
|---|---|---|
| **多阶段处理**（L1→L2→L3→L4） | 每阶段有独立的 thinking + 输出 + 落盘 | ✅ 保证准确性（0 幻觉 vs B 的 39s 幻觉） |
| **诚实度报告** | 强制 21 条观看证据 | ✅ 可追溯、可审计 |
| **Schema 校验 + QA** | L3 pro_qa_inspector 检查 | ✅ 一致性校验（VO ratio ✅ vs B ❌） |
| **密度门禁** | 要求 ≥3.3 镜头/10s | ⚠️ 门禁设了但本次未生效（A 实际 1.8） |
| **thinking_level=HIGH** | 每段独立感知 | ⚠️ 速度代价大，但准确性收益明确 |
| **view_file 全片观看** | 117.84s 视频完整感知 | ✅ 这是正确的做法（B 虽被要求但未做到） |

### 核心结论

> **Skill 慢的代价换来了：零幻觉 + 诚实度报告 + VO 一致性校验。**
> **直接 prompt 快的代价是：39 秒幻觉 + 126% VO ratio + 无诚实度报告。**
>
> 但 Skill 也有自身问题：**密度门禁未生效**（镜头密度 1.8 远低于自设的 3.3 最低线），说明 skill 的质量闸门在本次运行中没有真正拦截低密度输出。

## 六、改进建议

### 6.1 Skill 侧

1. **密度门禁生效化**：L2 完成后应自动计算 `shot_density`，低于 3.3/10s 直接打回重做，而不是放行
2. **ASL 过长告警**：A 的 ASL=5.61s（B=3.83s），skill 应在 ASL>4s 时提示"镜头切分不够细"
3. **诚实度报告自动化校验**：`honesty_report.view_duration_sec` 应与 `_video_meta.json.duration_sec` 自动比对

### 6.2 直接 prompt 侧（如要替代 skill）

1. **必须注入真实时长**：prompt 中写明 "视频总时长 117.84 秒，所有时间戳不得超过此值"
2. **必须要求结构化 ducking**：明确 "ducking_and_silence 必须是数组，每个元素含 start_sec/end_sec/ducking_attenuation_db"
3. **必须要求 emotion_curve 为列表**：明确 "visual_emotion_curve 必须是数组，每个元素含 start_sec/end_sec/emotion/intensity"
4. **必须要求 honesty_report**：明确 "输出必须包含 _meta.honesty_report，列出从观看中获得的至少 10 条具体细节"
